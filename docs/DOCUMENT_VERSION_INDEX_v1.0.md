## 🏷️ Version Numbering System

### Filename Format: `DOCUMENT_NAME_v[Major].[Minor].md`

**Major Version (v1.0, v2.0, v3.0):**
- Complete rewrites
- Major feature additions
- Breaking changes
- Fundamental restructuring

**Minor Version (v1.1, v1.2, v2.1):**
- Content updates
- Small improvements
- Additional sections
- Clarifications

**Examples:**
- `TRANSLATIONS_v1.0.md` → Initial version
- `TRANSLATION_WORKFLOW_v1.1.md` → Updated with new examples
- `STATIC_ASSETS_AND_CACHE_v1.0.md` → Manifest + BUILD_ID + nginx (2026)
- `README_v3.1.md` → Major reorganization + file versioning update

## 📁 File Versioning Benefits

### Why Version Numbers in Filenames?

✅ **Instant Identification**
- No need to open files to see version
- File explorer shows version at a glance

✅ **Chronological Sorting**
- Files sort naturally by name
- Easy to identify progression

✅ **Historical Tracking**
- Keep multiple versions if needed
- Clear evolution of documentation

✅ **Git-Friendly**
- Version changes visible in commits
- Easy to track file updates

### Example: Version Evolution
```
TRANSLATIONS_v1.0.md       (Initial)
TRANSLATIONS_v1.1.md       (Updated examples)
TRANSLATIONS_v2.0.md       (Complete rewrite)
```
